1. Введение
1.1 Цель
Создать единую внутреннюю веб-платформу для управления персоналом всей компании Болашак — магазины, РЦ, АУП, маркетинг, бухгалтерия, IT, служба безопасности. Платформа заменяет разрозненные Google Sheets, мессенджерные переписки и бумажные документы.

4. Функциональные модули
4.1 База сотрудников
Единый реестр всей компании. Источник правды для всех модулей.


Карточка сотрудника
* ФИО, дата рождения, фото
* Подразделение (unit_id), должность
* Тип занятости: полная ставка / неполная / почасовая / договор ГПХ
* Оклад (тенге) или ставка часа. Для ГПХ — фиксированная сумма
* Дата приёма, конец испытательного срока
* Телефон, Telegram username
* Контакт экстренной связи
* ИИН (зашифрован AES-256)
* Статус: active / on_leave / terminated


История
* Лог переводов между подразделениями (дата, причина, кто инициировал)
* История изменений оклада и должности


  При переводе сотрудника: старый руководитель теряет доступ, новый получает. HR и admin видят полную историю.


4.2 Табель учёта рабочего времени
Логика ввода зависит от типа графика подразделения.


Режим SHIFT — Магазины, РЦ, СБ
* Руководитель заполняет матрицу: сотрудники × дни месяца
* Типы ячеек: Д (день), В (вечер), Н (ночь), В (выходной), О (отпуск), Б (больничный), К (командировка)
* Длительность смен настраивается для каждого подразделения отдельно
* Система автоматически считает итог часов и подсвечивает нарушения нормы
* Дедлайн заполнения: 1-е число следующего месяца. Telegram-напоминание 28-го.


Режим STANDARD — АУП, Маркетинг, Бухгалтерия
* Система авто-генерирует табель по производственному календарю РК (рабочие дни = 160 ч)
* Руководитель ТОЛЬКО отмечает отсутствия: отпуск / больничный / прогул / командировка
* Нет матрицы — экономия времени офисных руководителей


Режим FLEXIBLE — IT
* Руководитель вводит только итоговые часы за месяц по каждому сотруднику
* Нет матрицы, нет детализации по дням


Общий процесс (все режимы)
Статус
	Кто
	Действие
	draft
	Система (1-го числа)
	Открыт для заполнения руководителем
	submitted
	Руководитель
	Заполнен, ожидает проверки HR
	approved

	rejected

	Возвращён с комментарием на доработку
	

4.3 ЗП ведомость и авансы
Единая ведомость по всем подразделениям. Галина работает в одном месте с фильтрацией по подразделению/типу.


Расчёт базовой ЗП (по типу подразделения)
Тип занятости / подразделения
	Формула расчёта
	Оклад + shift/shift_mixed (магазины, РЦ, СБ)
	Оклад × (Факт часов ÷ Норма месяца)
	Оклад + standard_5_2 (офис)
	Оклад × (1 − Доля отсутствий). Нет отсутствий = полный оклад
	Оклад + flexible (IT)
	Оклад × (Введённые часы ÷ 160). Или фиксированная сумма — настраивается
	Почасовая оплата
	Ставка_часа × Факт_часов
	ГПХ (договор подряда)
	Фиксированная сумма, вводится Галиной вручную
	

Заявки на аванс
* Руководители shift-подразделений (магазины, РЦ, СБ) подают заявки на своих сотрудников
* АУП и офис: Айзада вводит напрямую в ведомость (как сейчас)
* Лимит: 50% от начисленного на дату подачи. Новые сотрудники (<3 мес.): 50% от часов из табеля
* Система блокирует превышение и показывает максимальную допустимую сумму
* Дедлайн подачи: 20-е число


Корректировки Галины
* Штрафы из модуля «Дисциплина» подтягиваются автоматически
* Ручные доначисления: премия, матпомощь, компенсация — с обязательным полем «Основание»
* Итого = Начислено − Аванс − Удержания + Надбавки


Экспорт
* Ведомость аванс (25-е) и основная ЗП (до 10-го) — Excel
* Фильтры: по подразделению, типу подразделения, месяцу
* Сводный ФОТ-отчёт по всей компании

* Шаг 1: Заявку создаёт сотрудник или руководитель подразделения

  Для АУП: согласование сразу у Талшын, без промежуточного шага руководителя.


4.5 График смен
Модуль активен только для shift и shift_mixed подразделений (магазины, РЦ, СБ). Для офисных подразделений скрыт.


* Матрица: сотрудник × дни месяца × тип смены
* Длительности смен настраиваются для каждого подразделения
* Система считает итог часов, подсвечивает нарушения нормы
* Предупреждение: два ключевых сотрудника в отпуске одновременно
* После публикации: сотрудники видят свой график в личном кабинете

9. Нефункциональные требования


Безопасность
* Пароли — bcrypt (cost factor 12)
* JWT в httpOnly cookie
* ИИН — AES-256 шифрование
* Middleware проверяет роль + unit_id scope на каждом запросе
* Audit log: кто, что, когда изменил в данных сотрудников


Производительность и доступность
* Загрузка страницы < 2 сек на внутренней сети
* До 20 пользователей одновременно
* Адаптивный дизайн для мобильных браузеров (руководители магазинов)
* TailScale доступ: 100.121.80.67:3002
* PM2 — автозапуск после перезагрузки сервера
