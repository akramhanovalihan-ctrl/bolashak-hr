## Сценарий на видео

1. Табель **АУП, май 2026** — попытка добавить сотрудника через поиск «Нагашыбаева Талшын» → **«Сотрудник не найден»**
2. **База сотрудников** — поиск «талшын» → она в **HR-отделе**, не в АУП
3. В табеле май строка «нагашыбаева» / должность «Ассистент собст…» — ручной ввод без связи с базой
4. Табель **июнь 2026, утверждён** — корректно: **Калымбек Нурасыл** (ассистент) + **Мейрманова Айзада**
5. **ЗП ведомость, июнь** — фильтр «АУП», но в таблице **99 сотрудников** всех подразделений

## Исправления

| # | Проблема | Решение |
|---|----------|---------|
| 1 | Поиск ФИО вместо списка | `<select>` с сотрудниками подразделения |
| 2 | Нагашыбаева не находится в АУП | Подсказка: список только своего подразделения; она в HR-отделе |
| 3 | «нагашыбаева» без привязки к базе | Удаление tmp-строк при синхронизации табеля; запрет ручного создания |
| 4 | Ведомость 99 чел. при фильтре АУП | Загрузка только после выбора подразделения; sync только по утверждённым табелям; убран пункт «Все подразделения» |
| 5 | Колонка ФИО пропадает при прокрутке | Шире sticky-колонка ФИО |
| 6 | Калымбек в оргструктуре | Исправлен тип узла; парсер: прямые подчинённые собственнику → АУП |

## Важно для пользователя

- **Нагашыбаева Талшын** — HR-отдел, табель **АУП** её не содержит (это правильно).
- **Ассистент собственника** в АУП — **Калымбек Нурасыл** (из оргструктуры).
- Чтобы сотрудник попал в табель подразделения — он должен быть привязан к этому подразделению в **Базе сотрудников**.
